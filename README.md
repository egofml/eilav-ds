# EILAV DS

위탁판매 자동화를 다른 PC와 다른 ChatGPT/Codex 계정에서도 사용할 수 있게 만드는 프로젝트.

현재 상태: 공유 구조와 개발 원칙만 정의한 초기 단계. 판매처 연동, 설치 프로그램, 자동화 실행 기능은 아직 구현하지 않았다.

GitHub 저장소: https://github.com/egofml/eilav-ds (비공개)

## 다른 PC에서 받기

1. 저장소 소유자가 함께 사용할 사람의 GitHub 계정을 협업자로 초대한다.
2. 초대받은 사람은 초대를 수락하고 본인 GitHub 계정으로 로그인한다.
3. Git을 사용하는 경우 아래 명령으로 받는다. Git 없이 받을 때는 저장소의 Code → Download ZIP을 사용해 압축을 푼다.

```sh
git clone https://github.com/egofml/eilav-ds.git
```

4. 본인 계정으로 로그인한 Codex에서 받은 프로젝트 폴더를 연다. README.md와 AGENTS.md를 읽고 작업을 이어가도록 요청한다.
5. 판매처 연결 기능이 추가되면 각자 자기 계정으로 초기 설정을 진행한다. 현재는 설계 문서만 제공한다.

Git으로 받은 프로젝트는 로컬 변경을 정리한 뒤 프로젝트 폴더에서 `git pull --ff-only`로 업데이트한다. ZIP으로 받은 경우 새 배포본을 별도 폴더에 풀고 개인 설정과 데이터는 보존한다.

## 공유 구조

- 코드, 업무 절차, Codex 프로젝트 지침, 설정 예시를 Git 저장소에 함께 관리한다.
- 배포 경로는 GitHub 저장소 또는 검토된 배포 ZIP을 우선 고려한다.
- 사용자는 자기 PC에 프로젝트를 받고 자기 Codex 계정으로 폴더를 연다.
- 판매처·공급처 로그인, API 키, 연결 권한은 사용자별로 설정한다.
- 기존 대화나 개발자 개인 메모리에 의존하지 않도록 실행 절차와 결정 사항을 저장소에 기록한다.
- 재사용할 업무가 확정되면 `.agents/skills/`에 프로젝트 스킬을 제공한다. 여러 프로젝트에서 설치해 쓸 필요가 생기면 플러그인 패키징을 검토한다.

## 코드 공유와 데이터 연동

기본은 같은 자동화를 각자의 계정과 데이터로 독립 실행하는 방식이다. 상품·주문·재고를 여러 사용자가 함께 다뤄야 한다면 별도 공유 저장소 또는 서버와 사용자별 권한을 설계한다. GitHub 코드 업데이트는 판매 데이터 동기화를 의미하지 않는다.

## 구현 요구사항

1. 특정 PC의 절대 경로, 개발자의 로그인 세션 및 개인 계정에 의존하지 않는다.
2. 사용자 데이터와 인증정보는 코드 밖에 보관한다. 저장소 내부에서 필요한 로컬 파일은 `local/`에 둔다.
3. 초기 설정 안내, 필수 도구 검사, 설정 예시, 샘플 데이터 실행을 제공한다.
4. 업데이트 시 사용자 설정과 작업 데이터를 보존한다.
5. 외부 변경 전 미리보기와 중복 실행 방지, 실행 결과 기록을 구현한다.
6. 실제 다른 PC와 다른 계정으로 설치부터 결과 확인까지 검증한 뒤 이식성 완료로 보고한다.
7. 배포 파일은 명시적인 허용 목록으로 구성하고 인증정보·개인정보 포함 여부를 점검한다. `.gitignore`만으로 ZIP 배포 보호를 대신하지 않는다.
